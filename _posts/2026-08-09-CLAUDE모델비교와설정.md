## 모델 비교

| 기능 | Claude Fable 5 | Claude Opus 5 | Claude Sonnet 5 | Claude Haiku 4.5 |
|---|---|---|---|---|
| **설명** | 장시간 실행되는 에이전트를 위한 차세대 지능 | 복잡한 에이전트 코딩과 엔터프라이즈 작업용 | 속도와 지능의 최상의 조합 | 프론티어에 가까운 지능을 갖춘 가장 빠른 모델 |
| **입력 가격** (100만 토큰당) | $10 | $5 | $3 | $1 |
| **출력 가격** (100만 토큰당) | $50 | $25 | $15 | $5 |
| **컨텍스트 윈도우** | 1M 토큰 | 1M 토큰 | 1M 토큰 | 200k 토큰 |
| **최대 출력** | 128k 토큰 | 128k 토큰 | 128k 토큰 | 64k 토큰 |
| **적응형 사고** | 예 (항상 켜짐) | 예 | 예 | 아니요 |
| **확장 사고** (`thinking.type: "enabled"`) | 아니요 | 아니요 | 아니요 | 예 |
| **상대적 지연 시간** | 느림 | 보통 | 빠름 | 가장 빠름 |
| **신뢰할 수 있는 지식 기준일** | 2026년 1월 | 2026년 5월 | 2026년 1월 | 2025년 2월 |
| **학습 데이터 기준일** | 2026년 1월 | 2026년 5월 | 2026년 1월 | 2025년 7월 |

모델마다 속도/비용/지능의 정도가 서로 다르다.

Fabel 지능이 가장 높지만, 비교적 응답시간이 느리다. 그리고 비용도 비싸다.

간단한 작업인데 Fabel을 사용하면 작업속도가 느리고, 비용도 낭비이므로 적합하지 않다.

그러므로, 각 모델들의 특징들을 고려하여 작업 상황에 맞게 모델을 선택해서 사용하는 것이 비용도 절약할 수 있고 효율적으로 작업할 수 있다.

예시)
- Fable5: 밤새 돌리는 자율 에이전트, 대규모 마이그레이션, deep 리서치
- Opus5: 복잡한 에이전트 코딩, 멀티파일 리팩터링, 아키텍처 설계
- Sonnet5: 일상 코딩 대부분, 기능 구현, 테스트 작성
- Haiku 4.5: 분류·요약·포맷 변환, 파일 읽기, 서브에이전트 워커

[참고문서](https://platform.claude.com/docs/ko/about-claude/models/overview)

## 모델 설정 방법

### 모델 별칭

모델 ID를 그대로 쓰는 대신, 아래 별칭을 쓰면 항상 해당 계열의 최신 모델이 잡힌다.

| 별칭 | 동작 |
|---|---|
| `default` | 모델 재정의를 제거하고, 계정 유형에 따른 권장 모델 또는 관리자가 설정한 조직 기본 모델로 되돌린다. 그 자체가 모델 별칭은 아니다 |
| `best` | 조직에서 액세스할 수 있으면 Fable 5, 아니면 최신 Opus 모델 |
| `fable` | 가장 어렵고 오래 실행되는 작업용 Claude Fable 5 |
| `opus` | 복잡한 추론 작업용 최신 Opus 모델 |
| `sonnet` | 일일 코딩 작업용 최신 Sonnet 모델 |
| `haiku` | 간단한 작업용 빠르고 효율적인 Haiku 모델 |
| `opus[1m]` | 긴 세션을 위해 100만 토큰 컨텍스트 윈도우를 쓰는 Opus |
| `sonnet[1m]` | 긴 세션을 위해 100만 토큰 컨텍스트 윈도우를 쓰는 Sonnet. `sonnet`이 이미 1M 윈도우가 기본인 Sonnet 5로 잡히면 효과가 없다 |
| `opusplan` | Plan Mode에서는 `opus`, 실행 단계에서는 `sonnet`으로 전환하는 특수 모드 |


모델 설정 방법은 아래 네 가지 방법이 있으며, 적용 우선순위는 다음과 같다.

### 1. 세션 중: `/model <alias|name>`
- 작업 도중에 즉시 전환한다. 별칭과 모델 ID 둘 다 받는다.
- `/model`을 인수 없이 실행하면 선택기가 열린다.
- 대화에 이전 출력이 있으면 확인을 한 번 요청하는데, 모델을 바꾸면 다음 응답이 캐시된 컨텍스트 없이 전체 기록을 다시 읽기 때문이다.

```bash
/model sonnet
```

### 2. 시작 시: `claude --model <alias|name>`

- 해당 실행에만 적용된다. 
- 설정 파일 값을 일회성으로 덮어쓸 때 쓴다.

```bash
claude --model sonnet
claude --model claude-haiku-4-5
```

### 3. 환경 변수: `ANTHROPIC_MODEL=<alias|name>`

- 셸 환경 전체에 적용된다. 
- 한 번만 적용하려면 앞에 붙여서 실행한다.

```bash
export ANTHROPIC_MODEL=sonnet
```

### 4. 설정 파일: `model` 필드

- 영구적으로 고정된다. 
- 사용자 전역은 `~/.claude/settings.json`, 프로젝트 단위는 저장소의 `.claude/settings.json`에 둔다.

```json
{
  "model": "sonnet"
}
```

[참고문서](https://code.claude.com/docs/ko/model-config#setting-your-model)

## 결론

하나의 모델을 고정해두고 모든 작업을 처리하는 것은 효율적이지 않다.

간단한 작업에 고성능 모델을 쓰면 속도도 느리고 비용도 낭비된다. 반대로 복잡한 작업에 낮은 성능의 모델을 쓰면 결과물이 기대에 못 미쳐서 결국 다시 작업하게 된다.

정리하면 이렇게 쓰는 것이 좋다.

- 기본값은 **Sonnet** 계열로 두고 일상적인 코딩 작업을 처리한다.
- 아키텍처 설계, 대규모 리팩터링, 소스코드 분석처럼 판단이 많이 필요한 작업은 **Fable** / **Opus** 계열로 올린다.
- 포맷/네이밍 변환처럼 단순 작업은 **Haiku** 계열로 내린다.

설정은 프로젝트의 `.claude/settings.json`에 기본 모델을 지정해두고, 작업 성격이 달라질 때 세션 중에 `/model`로 전환하는 방식이 편하다.

결국 중요한 건 지금 하는 작업이 어느 수준의 판단을 필요로 하는지 스스로 판단하는 것이다.
